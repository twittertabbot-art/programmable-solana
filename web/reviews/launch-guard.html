Launch guard

A report on one of the platform's own hooks, written from its code.

For a window after launch, a buy pays a higher pool fee that falls every slot to the pool's own fee. The extra fee stays in the pool. Nobody collects it, and sells are never touched.

Its code is programs/hook_launch_guard/src/lib.rs in the package.

    What it does

    The launcher sets a start fee and a window when the coin launches. While the window runs, the hook replaces the pool fee of every buy with a fee that starts at the start fee and falls in a straight line, slot by slot, to the pool's own fee. After the window the pool works as if it had no hook.

    The extra fee is a pool fee, so it stays in the pool's reserves. On a launch of this site all of the pool's liquidity is locked, so the fee deepens the pool for every holder.

    Who controls the program

    This is one of the platform's own hooks. Its upgrade authority is a key of Programmable that the platform whitelists, so the pool takes it without approval.

    Programmable's key can still upgrade it. An upgrade could change anything this report says. Programmable answers for it as it answers for the pool program itself.

    When it runs

    MomentCalledWhat it does then
    A buyyes, before the tradeWhile the window runs, answers the falling pool fee. After it, answers nothing.
    A sellnever
    Adding liquidityyes, before the depositRefuses the deposit while the window runs.
    Removing liquiditynever
    Pool creationonceChecks the pool, and starts the window in that slot.

    Its manifest flags are BEFORE_SWAP, BEFORE_ADD_LIQ, ON_POOL_CREATE, OVERRIDE_FEE, CALL_ON_BUY.

    What it can take, and where it goes

    The hook takes nothing for any wallet. It only sets the pool fee of a buy during the window.

    The program refuses a start fee above 50% and a window longer than 10,800 slots, about 72 minutes. The pool also cuts the fee to the platform's override cap, now 50%. The fee only falls. It reaches the pool's own fee when the window ends.

    The fee stays in the pool's reserves, like any pool fee.

    Can it refuse a trade

    It never refuses a buy or a sell. The pool never calls it on a sell.

    It refuses one thing, a deposit of liquidity while the window runs. A deposit in the launch slot could otherwise take most of a sniper's fee out again. Taking liquidity out is never refused.

    What can change after launch, and who changes it

    Nothing. The settings have no owner, and no instruction changes them after the pool exists.

    InstructionWhoWhat it does
    init_pool_configthe launcher, onceCreates the settings, the start fee and the window, before the pool exists.
    init_manifestthe upgrade authority, onceWrites the manifest and the list of extra accounts.
    on_pool_createthe pool only, onceRecords the slot the window starts in.
    before_swap, before_add_liquiditythe pool onlyThe calls above. They change nothing.

    Its manifest and its account list

    init_manifest writes both once. It needs the program's upgrade authority, and an account that exists cannot be created again. No instruction rewrites either of them. The list names one account, the coin's guard settings, which the pool passes writable so that pool creation can record the start slot.

    Programs it calls

    The system program, to create its accounts at setup. No other program.
