Build a custom hook

A hook declares its powers once, as flags in its manifest. A pool copies them when it is created and keeps them forever. Tick what your hook needs and nothing more.

        The folder hook-template of the package is a complete hook with its tests and its scripts. Copy it, name your program and change the code. The commands run in Linux or WSL, from the root of the package.
        
          
        
            
        
              
        Copy, rename, test
        
              
        cp -r hook-template my-hook
cd my-hook
bash scripts/rename.sh fee_split
bash scripts/test.sh
        
              
        The tests load your hook next to the real pool program, without a validator. Test before you freeze. Every fix after the freeze is a new program at a new address.
        
              
        Build
        
              
        bash scripts/build.sh
        
              
        The build prints your program id. Step 3 needs it.
        
            
        
            
        
              
        Start the local chain
        
              
        bash build.sh build
bash scripts/localnet.sh up
node scripts/init-platform.mjs localnet
        
              
        The pool program runs on a local validator only. It is not on devnet and not on mainnet. Run these from the root of the package.
        
              
        The README of hook-template explains every script.

          Get it reviewed first
          
              
          Put the code in a public repository and send a review request with its commit. You pay the review fee of 25 USD in SOL in the same step. Programmable reviews that commit against ten rules.
          
              
          Once the code passes, deploy exactly that commit with the command below and freeze it. A change after the review is a new program and a new review.
          
            
          
            Get your hook reviewed
          
          
          
          After the code passed
          
          
          
            
          
              
          The address and the pin
          
              
          Host hook.json at an address that ends in .json, will not change, and that other sites may read. Your manifest stores the link once, when you deploy. It holds 128 bytes.
          
              
          The link can pin your text. The deploy script adds a pin to the link. The pin is 22 characters made from the SHA-256 of the hosted file. From then on a site refuses any other file at that address. The pin takes 25 of the 128 bytes, so an address of up to 103 bytes can be pinned. A longer address works without the pin, and sites then say that you can still change the text.
          
              
          A pin proves that the file is the one you pinned. It is not a signature, and it says nothing about your code.
          
            
          
            
          
              
          
                
                
          
              
          
              
          Type the address and the deploy command appears here.
          
              
          
              
          
              
          The script reads the hosted file. It stops if the file names another program or is not the file the link pins. Then it deploys, publishes the manifest and removes the upgrade authority. Freezing cannot be undone, and the rent of a frozen program never comes back.
          
            
          
          
          
          
          
            
          Then give the program id on your request's page. Programmable checks on chain that the program is frozen and is the build of the reviewed commit, and puts it on the approved list. The hook is then listed in Custom hooks with the mark Reviewed by Programmable. The launch form reads your descriptor and offers your settings to every launcher.
